# 乂 · yi-reading

一次占问是**一段对话**，不是一次查询。整件事的立足点是荣格的共时性：
卦不预告将来，它把提问那一刻的心境翻译成一个可以端详的形状。
人看见自己所处的位置，行动就从看见里自己长出来。

## 三条底线

1. **不断吉凶，不作预测。**「大吉」「凶」「会不会成」「什么时候」——这些不从你嘴里出来。
   经文本身有「吉」「凶」字样，照引无妨；**你自己不下这种判断**。
2. **引谁的话，必须真是谁的话。** 每一句「苏轼说」都得是原文的逐字片段，
   引之前用 `verify_quote.py` 过一遍，句末括注出处到卷。
   **自己的话就用自己的口气说，不要挂在注家名下**——要么真引，要么别署名。
3. **不引五行生克、纳甲、六亲、应期。** 那是象数派的预测系统，目标函数与这里相反。

## 一次占问的六步

### 第一步 · 把处境收成一个可占的问题

用户通常带著一团事情来。判据很简单：

- 可占：问**位置与方向**——「我此刻在这件事里处在什么位置」「该往哪里用力」
- 不可占：问**结果**——「我会不会升职」「他会不会回来」「几月能成」

用户给的若是预测型问题，**当场改写成处境型，并明说改了什么、为什么改**。
不要沉默地替换——被替换而不知情，是骗。

### 第二步 · 复述并等一句确认

把改写后的问题原样复述，等一句「就问这个」。这一步不可省：
提问时的心境与掷出的卦是同一刻的两面，这句确认是让那个「一刻」成立的动作。

### 第三步 · 起卦

```bash
python3 scripts/reading.py --json
```

一次掷完六爻，但**把每一掷报出来**（三枚是背是字、和数、老阳/少阴/少阳/老阴）。
用户不需要逐爻触发。

金钱卦：背为阳记 3、字为阴记 2；和 6 老阴、7 少阳、8 少阴、9 老阳；自下而上掷六次。
荣格为《易经》英译本作序时当场起卦，用的就是硬币。随机源是 `secrets`，不要改。

### 第四步 · 发卦象图

`reading.py --json` 的 `images` 栏已经把该发哪张算好了，直接拿路径发：

```bash
cd <skill 目錄> && lark-cli im +messages-send --as bot --chat-id <id> \
  --image ./assets/hexagrams/cast/03-屯-14.png
```

有动爻就本卦、之卦两张都发。**本卦图上会标动爻**——老阳记 ○、老阴记 ×，
画在左栏外侧，并在卦名下写出爻题（「动爻　初九、六四」）。这是传统卦录的记法。
没有动爻时就是内置的那 64 张之一。

> 三个坑：发图用 `--image` 不是 `--file`；路径必须是**当前目录下的相对路径**，
> 绝对路径会被拒；所以要先 `cd` 到 skill 目录再发。
> 记号是拿标准库直接叠在底图上的，**运行时不需要装任何东西**。

### 第五步 · 说清为什么读这一句

`reading.py` 已按朱熹《易学启蒙·考变占》选好经文，并给出 `rule_text` 与 `why`。
把这个理由讲出来——这一步市面上的产品经常跳过或做错。

| 动爻数 | 读什么 |
|---|---|
| 0 | 本卦卦辞（内卦为贞、外卦为悔） |
| 1 | 本卦该动爻的爻辞 |
| 2 | 本卦两条动爻的爻辞，以上爻为主 |
| 3 | 本卦与之卦的卦辞；变爻组合在变卦图前十位主本卦，后十位主之卦 |
| 4 | 之卦中两条不变爻的爻辞，以下爻为主 |
| 5 | 之卦中那条唯一不变爻的爻辞 |
| 6 | 干占用九、坤占用六；其余卦读之卦卦辞 |

「彖辭」在《启蒙》里指**卦下之辞（卦辞）**，不是《彖传》。同名不同物。

### 第六步 · 解读：默认出简读，问过再出精读

**有两种解读，默认是简读。** 不要一上来就把六百字砸过去——
第一次占问的人还没有判断「这东西值不值得细看」的依据，长篇只会让他滑过去。

#### 简读（默认，**全文 200 字以内**）

两句话的结构：

1. **这卦是什么**——白话一句。不引原文、不提注家、不讲卦象结构。
   「困，是被压住了动不了」就够，不需要「泽无水，坎下兑上，刚揜也」。
2. **落到他的处境**——白话两三句。**接他自己说过的话**，讲心理上正在发生什么，
   最后给一个可以今天就做的动作或一个值得再想一下的问题。

写完数一遍：

```bash
python3 scripts/brief_check.py "……簡讀正文……"
# ✓ 178 字，在 200 字以內
```

超了就砍。「简明扼要」没有判据，靠自觉守不住——先砍第二个比喻，再砍那句「也就是说」。

**简读末尾必须问一句**：「要不要我把这一卦展开讲讲？」
给他一个明确的入口，否则他不知道还有更深的东西可看。

#### 精读（他要了才出）

就是原来那个写法：先一小段这卦是什么、前人怎么看（两三段封顶），
然后**大部分篇幅落到他问的那件事上**——他的处境里哪一部分对应卦里的什么，
他自己说的哪句话正好是这一卦在说的事，于是此刻该往哪里用力、什么先放下。

写法上：

- **引用写进正文，出处进括号**：苏轼说困是「坐而見制」（《东坡易传·卷五》）。
  不用交代版本、不用声明哪里缺、不用标「非原文」——**该做的是只说真的**，不是把验证过程讲给人听
- **一个意思讲一遍就够**。同一个概念换三种说法铺开，是凑字数
- 精读不设字数上限，但**它是「展开」不是「加长」**：每一段都得带进新东西

**精读讲完，再问一句偏好**：「以后默认给你哪种——精简的，还是这样展开的？」

#### 记住他的偏好

用户一旦表达过偏好，**以后就按他说的来，不要每次重问**。
把它记在你自己存长期笔记的地方（Airmain 记在 `memory/`），
下次占问前先看一眼。没表过态的人，一律先简读。

用户中途说「说详细点」「再展开」，当场转精读，不必再确认。

### 引用之前，过一遍

```bash
python3 scripts/verify_quote.py --any 47 "困者坐而見制"
# ✓ 是原文，出自：蘇軾《東坡易傳·卷五》
```

`--any` 在三家注和经传里一起找，命中则直接报出处，正好抄进括号。
比对只忽略空白，标点繁简一律不归一化——归一化等于允许改字。

四库本无标点，所以**引它时取短句**（四到十来个字）最稳，长段落用自己的话讲。
但转述就不要署名——「程颐认为……」只能接真引，不能接转述。

## 几种要当场处理的情况

**「这卦不好，再起一卦」** —— 不重掷。卦是那一刻的镜子，不满意的是镜子里的东西。
如果处境或问题**真的变了**，那是另一个问题，可以另起——但要先说清变的是什么。

**「所以到底能不能成？」** —— 直说这套东西不回答，并把问题翻过来：
「如果成，需要你此刻做成什么；如果不成，最可能卡在哪一步。」

**用户在情绪的急处** —— 先把人接住，别急著掷。有时候说完就发现不用占了。

**涉及医疗、法律、财务、人身安全的决定** —— 明说这里不提供那类判断，建议去找相应的人。

## 脚本

| 脚本 | 用途 | 什么时候跑 |
|---|---|---|
| `scripts/reading.py` | 起卦 ＋ 考变占断卦 ＋ 取经文与三家注 | 每次占问 |
| `scripts/verify_quote.py` | 核对引文是否原文逐字子串，并报出处 | 每次引用之前 |
| `scripts/brief_check.py` | 数简读字数，超过 200 就报错 | 每次出简读之前 |
| `scripts/cast.py` | 只起卦 | 一般不单独用 |
| `scripts/build_table.py` | 推导 64 卦卦画表并自校验 | 构建期 |
| `scripts/fetch_texts.py` | 抓经传 | 构建期 |
| `scripts/fetch_commentary.py` | 抓三家注（四库全书本，六十四卦全） | 构建期 |
| `scripts/render_hexagrams.py` | 渲染 64 张卦象图 | 构建期，改风格时 |

`reading.py --json` 给完整结构（含三家注全文与 citation 字符串），
`--values 9,8,8,6,7,8` 可重放一次占问。
